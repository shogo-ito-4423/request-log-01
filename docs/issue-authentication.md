# C1：認証・所有者によるアクセス制御

対象M3。依存B5・B6。2026-11-08に利用者がC1全体を選択。

## 背景と合意

匿名で他人の要望を変更できる問題を解決する。
本人の設計回答：一般利用者は自分の要望の登録・更新・削除、全員の要望の一覧・詳細。
管理担当者は全操作。この方針で認証・認可・所有者の永続化を実装する。

## 実装と完了条件

- 全CRUDに認証を要求し、未認証・無効トークンを401、他人の変更を403にする。
- 一般利用者の自身のCRUD、他人の閲覧、管理担当者の全件操作を検証する。
- 所有者を認証情報から決め、入力による所有者・役割の偽装を拒否する。
- Alembic 0002で既存行を保持して所有者列を追加する。旧行は管理担当者のみ変更可能。
- 設定不備時の起動拒否、トークン失効、SQLite/PostgreSQLのCRUD・移行を検証する。
- 秘密の扱い・失効方法・起動手順・公開前の残課題を文書化する。

必要な技術：FastAPI Depends・HTTPBearer、SHA-256、SQLAlchemy、Alembic、pytest、Compose。
方式と制約は[認証運用](authentication.md)を参照。
