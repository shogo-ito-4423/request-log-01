# 業務改善リクエストを登録・追跡できる最小APIを作る

## 課題

業務改善の要望を一覧化し、担当者・優先度・進捗を追跡する最小限の仕組みがほしい。
1日版ではAPIとデータ保存、テストとCIを完成させ、第三者がコンテナで再現できるようにする。

## 受け入れ条件

- GET /health、POST /issues、GET /issues、GET /issues/{id}、PATCH /issues/{id} が動く。
- SQLiteに保存し、APIコンテナ再作成後もデータが残る。
- 不正な入力は422、存在しないIDは404になる。
- 正常系・異常系・部分更新・永続化のpytestが成功する。
- push / PR時にGitHub ActionsがコンテナでRuffとpytestを実行する。
- READMEに起動、操作例、テスト、停止、制約を記載する。
- ローカルマシンへのライブラリのインストール・設定変更を必要としない。

## 対象外

認証、クラウド公開、PostgreSQL移行、Alembic、削除・検索は後続版とする。
