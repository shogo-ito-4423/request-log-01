# 状態を指定して改善要望を一覧取得する

追跡先：[GitHub Issue #4](https://github.com/shogo-ito-4423/request-log-01/issues/4)。実装コミットは `24fad23`。検証結果と振り返りは[11月3日の学習記録](daily-learning-log.md)を参照。

担当者が対応中の要望を確認するとき、現状は一覧をページごとに取得し、不要な状態の要望を手元で取り除く必要がある。既存の `GET /issues` に任意の `status` 条件を追加する。

## 完了条件

- `open`、`in_progress`、`done` のいずれかを指定すると、その状態の要望だけを返す。
- 状態を省略した場合は従来の一覧と同じ結果を返す。
- 一致がなければ200と空配列、未定義の状態値なら422を返す。
- 条件に一致する一覧の中で、既存のID昇順・limit・offsetの仕様が保たれる。
- 状態が混在するデータでページ分割との併用をテストする。コンテナ内で既存テストを含めて検証し、READMEに操作例を追加する。

対象外：優先度による検索、DBスキーマの変更。目安：60〜75分。
